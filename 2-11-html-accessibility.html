2.11 — HTML Accessibility

Learn how to create HTML webpages that are usable and understandable by people with disabilities, including users who rely on keyboards, screen readers, magnification, voice control, and other assistive technologies.

🎯 Learning Objectives

By the end of this lesson, you should be able to:

  • Define web accessibility.
  • Explain why accessibility is important.
  • Understand the role of semantic HTML in accessibility.
  • Write useful alternative text for images.
  • Associate labels with form controls.
  • Use headings to create a logical page structure.
  • Create keyboard-friendly webpages.
  • Understand the purpose of ARIA.
  • Use accessible links and buttons.
  • Understand basic color and contrast considerations.
  • Use accessible tables and forms.
  • Apply accessibility principles to a webpage.

📖 1. What Is Web Accessibility?

Web accessibility means designing and developing websites and applications so that people with disabilities can use them effectively.

Accessibility can benefit people with:

  • Visual disabilities
  • Hearing disabilities
  • Motor disabilities
  • Cognitive disabilities
  • Speech disabilities

Accessibility also benefits users in temporary or situational circumstances, such as someone using a phone in bright sunlight or someone who cannot use a mouse.

🌎 2. Why Accessibility Matters

♿ Inclusion

Accessible websites help more people participate in digital experiences.

⌨️ Keyboard Access

Some users navigate websites without a mouse.

🔊 Screen Readers

Screen readers convert webpage content into speech or other forms of output.

📱 Better Usability

Many accessibility practices improve usability for everyone.

🏗️ 3. Semantic HTML and Accessibility

One of the easiest ways to improve accessibility is to use HTML elements according to their intended meaning.

Good: 
<nav>

    <a href="courses.html">
        Courses
    </a>

</nav>
Avoid using generic elements when a semantic element already describes the purpose: 
<div onclick="openCourses()">
    Courses
</div>

Semantic elements provide meaningful information to browsers and assistive technologies.

🖼️ 4. Alternative Text

Images should have appropriate alt text when the image provides meaningful information.

Good example: 
<img
    src="student-coding.jpg"
    alt="Student writing HTML code on a laptop">
Weak example: 
<img
    src="student-coding.jpg"
    alt="image">

The purpose of alternative text is to communicate the important information conveyed by the image.

🎨 5. Decorative Images

If an image is purely decorative and provides no meaningful information, an empty alt attribute can be used. 

<img
    src="decorative-line.png"
    alt="">
Remember:

Do not write "decorative image" as the alt text for every decorative image. If the image adds no useful information, an empty alt="" allows assistive technology to skip it.

📝 6. Accessible Headings

Headings provide structure and help users understand the organization of a webpage. 

<h1>
    Web Development Bootcamp
</h1>

<h2>
    HTML Fundamentals
</h2>

<h3>
    HTML Accessibility
</h3>

<h2>
    CSS Fundamentals
</h2>
Do not choose headings only because of their visual size.

Heading levels should represent the structure and hierarchy of the content.

🔗 7. Accessible Links

Link text should communicate where the link goes or what it does.

❌ Avoid 

<a href="courses.html">
    Click here
</a>

✅ Better 

<a href="courses.html">
    View Web Development Courses
</a>

🔘 8. Accessible Buttons

Use a real <button> element when the user performs an action on the current page. 

<button type="button">
    Submit Quiz
</button>

Use an anchor when the user is navigating to another resource or webpage. 

<a href="course-completion.html">
    View Course Completion
</a>

📝 9. Accessible Forms

Form controls should have clear labels.

Less accessible: 
<input
    type="text"
    placeholder="Enter your name">
Better: 
<label for="studentName">
    Student Name
</label>

<input
    type="text"
    id="studentName"
    name="studentName">

The for attribute on the label should correspond to the input's id.

⭐ 10. Required Form Fields

When a field is required, HTML can communicate this using the required attribute. 

<label for="email">
    Email Address
</label>

<input
    type="email"
    id="email"
    name="email"
    required>

📋 11. Fieldsets and Legends

Use <fieldset> and <legend> to group related form controls. 

<fieldset>

    <legend>
        Preferred Contact Method
    </legend>

    <label>

        <input
            type="radio"
            name="contact"
            value="email">

        Email

    </label>


    <label>

        <input
            type="radio"
            name="contact"
            value="phone">

        Phone

    </label>

</fieldset>

⌨️ 12. Keyboard Accessibility

A webpage should be usable by people who navigate with a keyboard rather than a mouse.

Common keyboard controls include:

  • Tab — Move between interactive elements.
  • Shift + Tab — Move backward.
  • Enter — Activate links and some controls.
  • Space — Activate buttons and certain controls.
Good Practice:

Use native HTML interactive elements such as <button> and <a> whenever possible.

🎯 13. Focus Indicators

Keyboard users need to know which element currently has focus. 

button:focus,
a:focus,
input:focus {

    outline: 3px solid #d4af37;
    outline-offset: 3px;

}
Never remove focus indicators without providing another visible focus style.

🎨 14. Color and Contrast

Text should have sufficient contrast against its background so that it can be read by users with low vision or color vision deficiencies.

❌ Poor Contrast

Difficult to read text

✅ Better Contrast

Easy to read text

Do not rely on color alone to communicate important information.

🧩 15. Introduction to ARIA

ARIA stands for Accessible Rich Internet Applications. ARIA provides additional information to assistive technologies when native HTML does not adequately communicate the behavior or state of an interface. 

<button
    aria-label="Close menu">

    ×

</button>
Important:

ARIA should not replace proper semantic HTML when an appropriate native HTML element already exists.

🏷️ 16. aria-label

The aria-label attribute can provide an accessible name when visible text is unavailable or insufficient. 

<button
    aria-label="Search">

    🔍

</button>

📊 17. Accessible Tables

Tables should have appropriate headers so users can understand the relationship between data cells and their headings. 

<table>

    <caption>
        Course Grades
    </caption>

    <thead>

        <tr>

            <th scope="col">
                Student
            </th>

            <th scope="col">
                Grade
            </th>

        </tr>

    </thead>


    <tbody>

        <tr>

            <td>
                Student 1
            </td>

            <td>
                92%
            </td>

        </tr>

    </tbody>

</table>

🌐 18. Document Language

The lang attribute identifies the primary language of a webpage. 

<html lang="en">

This information helps browsers and assistive technologies interpret the content correctly.

🏷️ 19. Page Titles

Every webpage should have a meaningful document title. 

<title>
    Web Development Bootcamp
</title>

A useful title helps users identify the page when navigating browser tabs, history, bookmarks, and assistive technology.

🗺️ 20. Accessibility Landmarks

Semantic elements create useful structural landmarks.

<header>

Introductory content.

<nav>

Navigation links.

<main>

Primary page content.

<aside>

Related secondary content.

<footer>

Footer information.

<section>

Thematic content group.

⏭️ 21. Skip Navigation Links

A skip link allows keyboard users to bypass repetitive navigation and move directly to the main content. 

<a href="#main-content"
   class="skip-link">

    Skip to main content

</a>


<main id="main-content">

    ...

</main>
Why is this useful?

Keyboard users should not have to repeatedly tab through the same navigation links every time they visit a page.

🏗️ 22. Complete Accessible HTML Example 

<!DOCTYPE html>

<html lang="en">

<head>

    <meta charset="UTF-8">

    <meta
        name="viewport"
        content="width=device-width,
        initial-scale=1.0">

    <title>
        Web Development Course
    </title>

</head>


<body>


    <a href="#main-content">
        Skip to main content
    </a>


    <header>

        <h1>
            Web Development Bootcamp
        </h1>

    </header>


    <nav aria-label="Main navigation">

        <a href="index.html">
            Home
        </a>

        <a href="courses.html">
            Courses
        </a>

        <a href="contact.html">
            Contact
        </a>

    </nav>


    <main id="main-content">


        <section>

            <h2>
                HTML Accessibility
            </h2>

            <p>
                Learn how to create accessible webpages.
            </p>

        </section>


        <section>

            <h2>
                Contact Instructor
            </h2>


            <form>

                <label for="name">
                    Name
                </label>

                <input
                    type="text"
                    id="name"
                    name="name"
                    required>


                <label for="email">
                    Email
                </label>

                <input
                    type="email"
                    id="email"
                    name="email"
                    required>


                <button type="submit">
                    Submit Question
                </button>

            </form>

        </section>


    </main>


    <footer>

        <p>
            © 2026 Golden Healing Solutions
        </p>

    </footer>


</body>

</html>

🧪 23. Accessibility Testing

Accessibility should be tested during development rather than only at the end of a project.

  • Navigate the page using only the keyboard.
  • Check that interactive elements receive visible focus.
  • Verify that images have appropriate alternative text.
  • Check heading structure.
  • Check form labels.
  • Check color contrast.
  • Test with browser accessibility tools.
  • Test with assistive technologies when possible.
Developer Mindset:

Accessibility should be considered throughout the development process.

🎓 27. Lesson Summary

Accessibility is a fundamental part of professional web development.

Accessible HTML uses meaningful structure, descriptive alternative text, properly labeled forms, keyboard-friendly controls, logical headings, appropriate color contrast, and other techniques to make websites usable by a wider audience.

The goal is not simply to make a website technically accessible. The goal is to create an experience that people with different abilities can successfully navigate and use.
