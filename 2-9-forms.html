2.9 — Forms & Input Types

Learn how HTML forms collect information from users and how different input types can be used to create professional, accessible, and interactive web forms.

🎯 Learning Objectives

By the end of this lesson, you should be able to:

  • Understand the purpose of HTML forms.
  • Create a form using the <form> element.
  • Use labels correctly.
  • Create text, email, password, number, date, and other inputs.
  • Use radio buttons and checkboxes.
  • Create dropdown menus using <select>.
  • Create multi-line text fields using <textarea>.
  • Use submit and reset buttons.
  • Understand required fields and basic validation.
  • Build accessible and user-friendly forms.

📖 1. What Is an HTML Form?

An HTML form allows a website to collect information from a user.

Forms are commonly used for:

  • Contact forms
  • Registration
  • Login pages
  • Search forms
  • Checkout pages
  • Surveys
  • Applications
  • Course enrollment
Basic Form 
<form>

    <label for="name">
        Name
    </label>

    <input
        type="text"
        id="name"
        name="name">

</form>

🏗️ 2. The <form> Element

The <form> element acts as a container for form controls. 

<form action="/submit" method="post">

    ...

</form>

action

Specifies where the form data should be sent.

method

Specifies how the form data is submitted. Common methods include GET and POST.

🏷️ 3. Labels

The <label> element identifies a form control.

The for attribute should match the input's id. 

<label for="email">
    Email Address
</label>

<input
    type="email"
    id="email"
    name="email">
Accessibility Tip:

Proper labels help screen-reader users understand what information belongs in each field.

⌨️ 4. Text Input

The text input allows users to enter a single line of text. 

<label for="fullname">
    Full Name
</label>

<input
    type="text"
    id="fullname"
    name="fullname">

📧 5. Email Input

The email input is designed for email addresses. 

<label for="email">
    Email Address
</label>

<input
    type="email"
    id="email"
    name="email"
    required>

The browser can perform basic validation to check whether the entered value resembles an email address.

🔐 6. Password Input

The password input hides the characters typed by the user. 

<label for="password">
    Password
</label>

<input
    type="password"
    id="password"
    name="password">
Important:

A password input hides characters visually, but secure password handling also requires appropriate server-side security and HTTPS.

🔢 7. Number Input

The number input is designed for numerical values. 

<label for="age">
    Age
</label>

<input
    type="number"
    id="age"
    name="age"
    min="1"
    max="120">

📅 8. Date Input

The date input allows users to select a date. 

<label for="birthday">
    Date of Birth
</label>

<input
    type="date"
    id="birthday"
    name="birthday">

The tel input is designed for telephone numbers. 

<label for="phone">

</label>

<input
    type="tel"
    id="phone"
    name="phone"

The url input is intended for website addresses.

</label>

<input
    type="url"
    id="website"
    name="website"
    placeholder="https://example.com">

🔎 11. Search Input

The search input is intended for search fields. 

<label for="search">
    Search
</label>

<input
    type="search"
    id="search"
    name="search">

📝 15. Textareas

The <textarea> element allows users to enter multiple lines of text. 

<label for="message">
    Message
</label>


<textarea
    id="message"
    name="message"
    rows="6"
    cols="40">
</textarea>

📎 16. File Uploads

The file input allows a user to select a file from their device. 

<label for="resume">
    Upload Resume
</label>


<input
    type="file"
    id="resume"
    name="resume">
Important:

Uploading and securely processing a file requires server-side handling. HTML alone does not permanently store the uploaded file.

🎚️ 17. Range Input

The range input creates a slider. 

<label for="experience">
    Experience Level
</label>


<input
    type="range"
    id="experience"
    name="experience"
    min="1"
    max="10"
    value="5">

🎨 18. Color Input

The color input allows users to select a color. 

<label for="brandColor">
    Brand Color
</label>


<input
    type="color"
    id="brandColor"
    name="brandColor"
    value="#d4af37">

👻 19. Hidden Inputs

A hidden input is not displayed to the user but can contain a value submitted with a form. 

<input
    type="hidden"
    name="course"
    value="web-development">
Security Warning:

Hidden inputs are not actually secure storage. Users can inspect and modify HTML in their browser. Never trust hidden form values for authorization or sensitive security decisions.

✅ 20. Required Fields

The required attribute prevents the form from being submitted until the field has a value. 

<label for="name">
    Full Name
</label>


<input
    type="text"
    id="name"
    name="name"
    required>

💬 21. Placeholder Text

The placeholder attribute provides an example or hint inside an input. 

<input
    type="email"
    placeholder="you@example.com">
Best Practice:

A placeholder should not replace a proper <label>. Labels should remain available so users can understand the field even after typing begins.

📏 22. min, max & maxlength

HTML provides attributes that can help limit or validate user input. 

<input
    type="number"
    min="1"
    max="100">


<input
    type="text"
    maxlength="50">

🔍 23. Pattern Validation

The pattern attribute can specify a regular expression that the entered value must match. 

<input
    type="text"
    name="username"
    pattern="[A-Za-z0-9]+"
    required>
Important:

Client-side validation improves the user experience, but server-side validation is still required for real applications.

⭐ 28. Form Best Practices

✅ Do

  • Use descriptive labels.
  • Use appropriate input types.
  • Mark required fields clearly.
  • Use helpful validation.
  • Keep forms organized.
  • Make forms mobile-friendly.
  • Use accessible controls.
  • Validate data on the server.

❌ Avoid

  • Using placeholder text instead of labels.
  • Collecting unnecessary information.
  • Making every field required.
  • Relying only on client-side validation.
  • Using unclear field names.
  • Making forms unnecessarily long.
