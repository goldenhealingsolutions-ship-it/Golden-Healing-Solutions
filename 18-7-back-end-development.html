18.7 — Back-End Development

Build the server-side functionality that powers your Capstone application, including routes, data processing, APIs, databases, authentication, and security.

🎯 Learning Objectives

  • Explain the role of back-end development.
  • Understand the client-server request/response cycle.
  • Select an appropriate back-end technology.
  • Create server-side routes and endpoints.
  • Connect an application to a database.
  • Create, read, update, and delete application data.
  • Process and validate user-submitted information.
  • Understand authentication and authorization.
  • Implement basic back-end security practices.
  • Connect the front end to the back end using APIs.

📖 What Is Back-End Development?

Back-end development is the server-side part of a website or web application.

While your front end controls what users see and interact with, the back end handles tasks such as processing requests, validating information, communicating with databases, authentication, and returning data to the client. :contentReference[oaicite:1]{index=1}

For example, when a user submits a registration form, the browser can send the request to the server. The server can validate the information, save it to a database, and return an appropriate response.

3. 🖥️ Server Configuration

Your server receives HTTP requests and determines how your application should respond.

A back-end application commonly includes routing, request processing, validation, business logic, database operations, and responses.

Server Code — Optional

4. 🛣️ Routes & Endpoints

A route connects a URL and HTTP method to server-side functionality.

Common HTTP methods include:

  • GET — retrieve information
  • POST — submit or create information
  • PUT/PATCH — update information
  • DELETE — remove information

For example:

GET   /api/products

GET   /api/products/:id

POST   /api/products

PUT   /api/products/:id

DELETE   /api/products/:id

5. 🔌 API Development

An API provides a structured way for different parts of an application to communicate.

Your front end may request data from your back end, and the server can return data such as JSON.

8. 📝 Server-Side Form Processing

Forms should not rely only on browser-side validation.

The server should validate submitted information before processing or storing it.

9. 🔐 Authentication & Authorization

Authentication vs. Authorization

Authentication determines who a user is.

Authorization determines what that authenticated user is allowed to access or do.

10. 🛡️ Back-End Security

⚠️ Security Is Part of Development

Never assume that information submitted by a browser is automatically trustworthy.

Your application should validate input, protect credentials and secrets, use appropriate authentication and authorization controls, and avoid exposing sensitive information.

11. 🔗 Connect Front End to Back End

Your completed front end should communicate with your back end when your Capstone requires dynamic data or server-side processing.

For example:

  • User submits a form.
  • JavaScript sends a request to the server.
  • The server validates the information.
  • The server communicates with the database.
  • The server returns a response.
  • The front end displays the result.

12. 🔑 Environment Configuration

Important:

Sensitive values such as database passwords, private API keys, and secret tokens should not be hard-coded into publicly accessible source files.

13. 🧪 Back-End Testing

14. 🚨 Error Handling

A professional application should provide appropriate responses when something goes wrong.

Examples include:

  • Invalid user input
  • Unauthorized requests
  • Missing resources
  • Database failures
  • Server errors
  • Network problems

15. ✅ Back-End Development Checklist

💡 Capstone Standard:

Your back end should support the actual requirements of your Capstone rather than adding unnecessary features.

A smaller application with properly implemented routes, validation, database operations, security, and error handling is better than a larger application with incomplete functionality.
