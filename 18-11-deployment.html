18.11 — Deployment

Take your completed Capstone application from development to a live production environment.

🎯 Learning Objectives

  • Explain the purpose of application deployment.
  • Prepare an application for production.
  • Select an appropriate hosting platform.
  • Configure production environment settings.
  • Configure environment variables and application secrets.
  • Deploy the application to a live environment.
  • Configure a production database when required.
  • Configure HTTPS and secure connections.
  • Verify the deployed application.
  • Perform post-deployment testing.
  • Document the deployment process.
  • Create a rollback or recovery plan.

📖 1. What Is Deployment?

Deployment is the process of making an application available in an environment where its intended users can access it.

For this Capstone, your goal is to move your completed application from your development environment into a live production environment.

Development → Production

Your application should first be tested in development or staging. Once it has been validated, it can be prepared for production deployment.

🚀 2. Deployment Stages

💻

Development

Build and modify the application locally.

🧪

Testing / Staging

Validate functionality before releasing the application.

🌎

Production

Make the application available to its intended users.

☁️ 3. Select a Hosting Platform

Choose a hosting platform appropriate for your application's technology stack.

Examples may include:

  • Static website hosting
  • Cloud application platforms
  • Virtual servers
  • Managed hosting
  • Container platforms
  • Full-stack application hosting

🛠️ 4. Production Preparation

Before deployment, review your application and remove development-only configuration, test data, debugging settings, and unnecessary files.

🔐 5. Environment Variables & Secrets

Important Security Rule

Do not place passwords, API keys, database credentials, private tokens, or other secrets directly into publicly accessible source code. Use your hosting platform's secure environment-variable or secret-management features when available.

🗄️ 6. Production Database

If your Capstone uses a database, make sure the production application connects to the correct production database.

Do not accidentally connect the live application to your development database.

🔒 7. HTTPS & Secure Connections

Production Security

A production application that handles user accounts or sensitive information should use HTTPS so data is encrypted while traveling between the user's browser and the application.

🌐 8. Domain & URL

🚀 9. Deploy Your Application

Follow the deployment instructions for your selected hosting platform.

Your deployment process may include:

  1. Connect your source repository or upload your files.
  2. Configure the build command if required.
  3. Configure the start command if required.
  4. Configure environment variables.
  5. Configure the database.
  6. Deploy the application.
  7. Wait for the deployment to complete.
  8. Open the live application.

🧪 10. Post-Deployment Testing

A successful deployment does not automatically mean the application works correctly in production. Perform a new round of testing against the live application.

🔥 11. Production Smoke Test

A smoke test is a short set of checks used to determine whether the most important functions of the deployed application are working.

⚡ 12. Production Performance

💾 13. Backup & Recovery

Why Backups Matter

A production application should have a recovery plan for important application data and configuration. Do not assume that a deployment platform automatically provides everything you need for recovery.
