Lesson Concept 01

Internet vs. World Wide Web

Though commonly used interchangeably in everyday conversation, the Internet and the World Wide Web (WWW) refer to two distinct layers of digital technology.

The Internet is the underlying global physical infrastructure—a massive interconnected network of computers, servers, cables, routers, and wireless systems spanning the globe.

The World Wide Web is a standardized service running on top of the Internet infrastructure that allows users to view, share, and navigate interlinked multimedia documents via web browsers using the HTTP protocol.

THE HIGHWAY ANALOGY Think of the Internet as a global network of physical roads and highways. The World Wide Web is one specific type of vehicle traveling on those roads (like delivery vans). Other services—such as Email (SMTP), File Transfer (FTP), and Online Gaming—are different vehicles using the exact same physical highway system.

🌐 THE INTERNET

  • Physical global network of hardware
  • Includes cables, satellites, and routers
  • Governed by IP and TCP protocols
  • Hosts multiple independent services
  • Established in the late 1969s (ARPANET)

💻 THE WORLD WIDE WEB

  • Software service operating on the Internet
  • Consists of HTML documents, assets, and APIs
  • Governed by HTTP/HTTPS protocols
  • Navigated using web browsers
  • Invented by Tim Berners-Lee in 1989
Lesson Concept 02

Clients, Servers, & Browsers

The modern web functions primarily on a Client-Server Model. This architecture divides tasks between resource requesters (clients) and resource providers (servers).

Entity Primary Function Examples
Client Devices and applications connected to the web that request data on behalf of the user. Laptops, smartphones, smart TVs, mobile apps.
Web Browser Software running on client devices that translates technical requests into visual, interactive UI. Parses HTML, CSS, and JS. Google Chrome, Mozilla Firefox, Apple Safari, Microsoft Edge.
Web Server Specialized hardware/software constantly connected to the web, listening for incoming client requests to process logic and serve files. Nginx, Apache, Node.js servers hosted on AWS, GCP, or Azure.
THE BROWSER ENGINE A web browser's main engine takes raw HTML, CSS, and JavaScript files returned by a server, parses the code, constructs the Document Object Model (DOM) and CSS Object Model (CSSOM), paints the visual interface onto your screen, and listens for user events.
Lesson Concept 03

HTTP & HTTPS Protocols

HTTP (Hypertext Transfer Protocol) is the foundational set of rules governing how data is structured, transmitted, and interpreted across the web.

HTTPS (Hypertext Transfer Protocol Secure) is the encrypted version of HTTP. It uses TLS/SSL (Transport Layer Security) protocols to encrypt data exchanged between client and server, preventing eavesdropping or tampering.

Common HTTP Request Methods

Method Action Purpose Real-World Example
GET Retrieve data from a server without modifying server state. Loading a blog post page.
POST Submit data to a server to create a new resource or process data. Submitting a registration form.
PUT / PATCH Update existing data stored on the server. Updating profile details.
DELETE Remove a specified resource from the server. Deleting a account comment.

Common HTTP Response Status Codes

Code Range Category Key Examples
2xx (Success) Request successfully received and processed. 200 OK, 201 Created
3xx (Redirection) Further action needed to complete the request. 301 Moved Permanently, 302 Found
4xx (Client Error) The request contained bad syntax or cannot be fulfilled. 400 Bad Request, 403 Forbidden, 404 Not Found
5xx (Server Error) The server failed to fulfill an apparently valid request. 500 Internal Server Error, 502 Bad Gateway, 503 Service Unavailable

Lesson Concept 04

Anatomy of a URL

A URL (Uniform Resource Locator) is a formatted web address that specifies the precise location of a resource on the web and the protocol used to retrieve it.

Complete URL Breakdown

https://www.goldenhealing.com:443/courses/web-dev?module=1&sort=asc#summary

Component Segment Description
Scheme / Protocol https:// Defines protocol for communicating with the resource (HTTPS, HTTP, FTP).
Domain / Hostname www.goldenhealing.com Human-readable name of the server holding the resource. Includes subdomain (www).
Port :443 Specific technical gate on server. (Port 80 for HTTP, Port 443 for HTTPS). Usually hidden.
Path /courses/web-dev Exact folder/file path to the requested resource on the server.
Query Parameters ?module=1&sort=asc Key-value parameters providing parameters to dynamic server scripts (starts with ?).
Anchor / Fragment #summary Points to a specific element ID within the loaded webpage (starts with #).
Lesson Concept 05

The Domain Name System (DNS)

Computers communicate using numerical addresses called IP (Internet Protocol) addresses (e.g., 192.0.2.1 for IPv4 or 2001:db8::1 for IPv6). Because humans are better at remembering words than numbers, the DNS serves as the internet's phonebook.

DNS translates human-readable domain names (e.g., goldenhealing.com) into computer-friendly IP addresses.

THE STEP-BY-STEP DNS LOOKUP PROCESS
1. Browser & OS Cache Check Checks local memory to see if IP is already known. If missing, queries DNS Resolver (ISP).
2. Root Nameserver Query Resolver asks Root Server (.), which directs resolver to Top-Level Domain (TLD) Server (.com).
3. TLD Nameserver Query Resolver queries .com TLD Server, which returns the Authoritative Nameserver IP.
4. Authoritative Nameserver Query Resolver asks Authoritative Server for goldenhealing.com and receives the destination IP address.

Lesson Concept 06

Web Hosting Infrastructure

Web hosting is a service where specialized server hardware and network infrastructure store website files and databases, making them continuously accessible to users worldwide 24/7.

Hosting Model How It Works Best Used For
Shared Hosting Multiple websites share compute resources (CPU, RAM, storage) on a single physical server. Beginner blogs, small personal sites, low traffic.
VPS (Virtual Private Server) Physical server is partitioned into virtual servers giving dedicated resource allocations. Growing businesses, custom apps, mid-range traffic.
Dedicated Server An entire physical server dedicated exclusively to a single client organization. High enterprise traffic, high security compliance needs.
Cloud Hosting Virtual cluster of connected servers dynamically scale resources on demand. Modern web apps, highly dynamic web applications (AWS, GCP).
Static Host / Serverless Files deployed directly across global Content Delivery Networks (CDNs) automatically. Modern front-end applications, JAMstack sites (Vercel, Netlify).
