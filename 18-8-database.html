18.8 — Database

Design, build, connect, secure, and test the database that supports your Capstone web application.

🎯 Learning Objectives

  • Explain the purpose of a database in a web application.
  • Identify the difference between relational and non-relational databases.
  • Select an appropriate database technology.
  • Design tables, collections, fields, and relationships.
  • Create a database structure for the Capstone.
  • Understand primary keys and foreign keys.
  • Perform CRUD database operations.
  • Connect the database to the back end.
  • Validate and protect database input.
  • Test database operations and error handling.
  • Document the database architecture.

📖 1. What Is a Database?

A database is an organized system for storing, managing, and retrieving information.

Web applications use databases when information needs to persist beyond a single browser session.

Examples of information that may be stored include:

  • User accounts
  • Products
  • Orders
  • Appointments
  • Course information
  • Messages
  • Job applications
  • Customer records

🔄 3. Relational vs. Non-Relational

Relational Database

Information is organized into tables consisting of rows and columns. Tables can be related through keys and relationships.

Examples: MySQL, PostgreSQL, SQLite.

Non-Relational Database

Information can be stored using structures such as documents, key-value pairs, graphs, or other models.

Example: MongoDB.

📋 4. Database Requirements

Before creating the database, identify exactly what information your application needs to store.

🏗️ 5. Database Design

Good database design begins by identifying the information your application needs and organizing that information into appropriate structures.

For a relational database, each table should represent a logical type of information.

🧱 6. Table Structure

A relational database table can contain fields that describe each record.

Field Data Type Key Purpose
id INTEGER PRIMARY KEY Unique user identifier
name VARCHAR — User's name
email VARCHAR UNIQUE User email
created_at DATETIME — Record creation date

🔑 7. Primary & Foreign Keys

Primary Key

A primary key uniquely identifies a record in a table.

Foreign Key

A foreign key can be used to establish a relationship between records in different tables.

🔗 8. Database Relationships

Common relational database relationships include:

  • One-to-One
  • One-to-Many
  • Many-to-Many

🔌 11. Connect the Database to the Back End

Your server should communicate with the database through an appropriate database driver, ORM, ODM, SDK, or database library.

✅ 12. Database Validation

Validate Before Storing Data

Data should be validated before it is inserted or updated in your database.

Examples include checking required fields, valid formats, appropriate lengths, valid ranges, and duplicate records.

🛡️ 13. Database Security

⚠️ Protect Database Information

Never expose database credentials in public source code.

Sensitive information should be protected using appropriate authentication, authorization, environment configuration, and secure application practices.
