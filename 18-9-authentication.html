18.9 — Authentication

Implement and document a secure authentication system for your Capstone web application.

🎯 Learning Objectives

  • Explain authentication and authorization.
  • Implement user registration.
  • Implement secure login and logout.
  • Validate authentication credentials.

  • Implement authenticated sessions.

  • Handle failed authentication attempts safely.
  • Implement password recovery when required.
  • Test authentication functionality.
  • Document the authentication architecture.

📖 1. Authentication vs. Authorization

🔑

Authentication

Authentication verifies that a user is who they claim to be.

Example: logging into an account.

🛡️

Authorization

Authorization determines what an authenticated user is allowed to access or do.

Example: an administrator accessing an admin dashboard.

👤

Identity

The application maintains information about the authenticated user and their permissions.

Key Concept:

A user being authenticated does not automatically mean that the user should have access to every resource in the application. Authentication and authorization should be treated as separate security decisions.

🧰 2. Authentication Technology

📝 3. User Registration

Registration allows a new user to create an account. Your registration process should validate submitted information before creating the account.

Typical registration information may include:

  • Name
  • Email address
  • Username
  • Password
  • Password confirmation

🔒 4. Password Security

Important Security Requirement

Passwords should never be stored as plain text. Use a password-hashing mechanism provided by a trusted framework or library. OWASP currently recommends modern password hashing approaches such as Argon2id, scrypt, bcrypt, or PBKDF2 depending on the application's requirements. :contentReference[oaicite:1]{index=1}

🚪 5. Login

The login process should verify the credentials submitted by the user and establish an authenticated session when the credentials are valid.

🎟️ 6. Session Management

After authentication, the application needs a secure way to recognize the authenticated user during subsequent requests.

Session identifiers should be unpredictable and handled using secure server/framework mechanisms. OWASP also recommends secure cookie configuration for authenticated sessions. :contentReference[oaicite:2]{index=2}

⚠️ Do Not Store Authentication Secrets in localStorage

Do not use this page's localStorage feature for real authentication credentials or tokens. OWASP warns that authentication tokens, session IDs, JWTs, and refresh tokens should not be stored in localStorage because JavaScript access can expose them if an XSS vulnerability exists. :contentReference[oaicite:3]{index=3}

🚪 7. Logout

Logout Requirement

Logging out should invalidate or terminate the authenticated session appropriately rather than merely hiding the user interface. :contentReference[oaicite:4]{index=4}

Use HTTPS for Authentication
